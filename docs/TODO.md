## 移动浏览器桌面网站验收

- [ ] 在 Android Chrome 中验证“桌面版网站”菜单开关及触摸交互，可使用实体设备或 Android 模拟器中的完整 Chrome。桌面浏览器自动化的合成 UA、触摸与视口上下文只验证环境信号组合，不能替代浏览器真实菜单切换。
- 验收步骤：记录 Android/Chrome 版本，关闭桌面版网站打开编辑器，确认移动布局；打开桌面版网站并重新加载，确认桌面布局；再次关闭并加载，确认恢复。再检查旋转或视口变化后的布局（包含约 980/740 CSS 像素宽度）、触摸选中与拖动、工具栏和面板开关、关闭后重新打开，以及是否出现触摸与鼠标事件重复触发。
- 声明 X11/Linux 或 X11/CrOS 桌面身份的触屏浏览器仍应使用桌面布局；Windows 触屏与 iPad 保留既有策略。窄屏桌面工作台通过滚动访问面板和工具栏。对照[运行环境与布局](architecture/runtime-environment.md)、[runtimeEnvironment.ts](../src/platform/runtimeEnvironment.ts) 与[浏览器回归说明](development/README.md#浏览器交互回归)记录设备信号和实际结果。未完成 Android Chrome 实际菜单验收前，不标记本项完成。

## 技能块的模拟执行链路

- [ ] 支持从技能块查看一次模拟中实际执行的步骤、条件结果与关联效果。

### 目标与首期范围

来源图回答“效果从哪里来”，执行链路回答“这次技能如何执行、为什么走到这里”。
首期提供“选择技能块 → 开启诊断记录并重跑 → 查看执行树 → 定位定义”的完整入口：

- 展示启动、费用、动作顺序、分支选择、等待与跳转、事件回调及结束或打断。
- 条件详情展示实际参与判断的值和结果；区分条件不满足、尚未到达与被中断。
- 关联已有伤害、Buff、资源和实体回执，复用详情与来源查询。
- 同步执行与延迟触发分别表达；技能结束后的 Buff 或实体回调作为关联分支展开。

预计难度中等，主要影响公共执行器的观察入口、应用层诊断记录和查看面板。先核实现有步骤身份与回执能覆盖的范围，再决定补充字段。

### 实现边界

- 在实际执行时记录条件结果，不事后重算条件或重新抽取随机数。
- 复用现有步骤、施法、Buff 和实体身份，只补必要的执行顺序与触发关系；不往每个 Hit 填完整来源链。
- 诊断观察不参与规则执行，不改变时序、资源或随机状态；记录不进入项目存档和战斗切面。
- 默认关闭详细记录。重跑绑定原输入、定义版本及种子，并明确标为诊断重跑；不能以当前已修改的方案冒充原模拟。
- 限制记录范围和数量，截断时明确提示。只筛选观察输出，不删去会影响目标技能的其他战斗输入。
- 不在首期提供每步完整状态快照、任意位置回退或完整调用栈调试器。
- 若需要逐干员、逐动作添加专用记录逻辑，先收束公共观察入口，不继续扩大修改面。

### 验收

- 开关记录不改变伤害、资源、状态和原有业务回执。
- 覆盖条件分支、同步嵌套事件、延迟回调、打断及随机行为，确认链路关联与定义定位正确。
- 输出保持结构化，供未来外部工具查询；本项不引入内嵌 Agent 或预先扩展整套 AI 协议。
