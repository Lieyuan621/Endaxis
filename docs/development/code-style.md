# 代码规范

本页约束手写源码、转换器和资源工具。目标是让游戏行为准确、职责清楚，并让后续修改容易验证。

## 先保证正确，再决定是否抽象

错误抽象不如有证据、边界清楚的专属实现。两个效果外观相似，不代表状态来源、触发顺序、时间域和结束条件相同。

证据只支持某个对象时，可以保留明确命名的专属实现，说明范围、依据和未知项，通过显式入口接入并保留回归。不能为了消灭特例虚构通用字段、放宽验证或改变原生行为。

## 用修改范围检验架构

动手前明确涉及的模块、输入输出和状态归属。小修改不要求另写方案。

如果同一信息反复穿过多层补字段，或每个新消费者都要求修改公共机制，先检查职责和依赖方向。不要只用“需要贯通”解释越来越大的改动。必要的跨层修改应说明每层为什么变化、下一项同类功能能否复用入口。

不设文件数量门槛，不为减少文件数合并无关职责，也不为尚未出现的需求搭框架。扩展代价过高时评估收益；分析功能宁可明确保留未分解部分，也不能扭曲模拟内核。

## 不把专属规则藏在通用代码中

禁止在公共编译、运行、投影和界面算法里按干员、技能、Buff、装备 ID、名称或前缀暗中切换规则。白名单、正则、哈希表或搬进 `utils` 不会改变它是特例的事实。

规则能由已有定义准确表达时归定义；独立原生行为归明确的专属实现。展示元数据归对象配置，专属外观归 `src/ui/operators/`，通用容器只负责选择、缩放与传参。

按公共动作种类或真实原生组件类型分派是正常职责，但必须读取对应字段、实现其真实语义。不能凭类型名字猜测规则，也不能用换 ID 测试代替原生证据。

移动规则归属与改变行为是两件事。后者必须重新核对依据，不借重构跳过验证。

## 数据、类型与状态

公共游戏定义使用 `packages/game-data-contract` 的唯一声明。部分字段从原类型选择，不复制同形定义，也不滥用类型工具掩盖概念不同。

类型依赖在文件顶部使用 `import type` 声明，不在字段或函数签名中写 `import('…').Type`。只有实际名称冲突时才使用别名；运行时按需加载保留动态 `import()`。生成模板遵循同一规则。

程序图按技能、Buff、能力实体及原生资源身份划分，禁止以干员、武器、装备或生成文件建立总图。不同独立资源不能因结构相同而合并；同一作用域内完全相同的分支先共享节点，仍有重复且有收益的中间段才提取宏。共享定义保留各调用位置及状态。折叠仅整理显示，不产生作用域，生成器不创建折叠图。具体规则见[动作图](../architecture/action-graphs.md)。

输入在明确边界校验，保留可选值、只读约束和判别联合。不要用 `any`、双重断言、填零或静默跳过掩盖缺失能力。

可恢复状态不得包含业务回调、运行类或闭包。程序只在受控步进中取得数据，不能把引用留到跨步进回调。恢复先准备完整装配再整体替换，不调用普通初始化；详情见[战斗切面](../architecture/checkpoints.md)。

观察层读取隔离副本或不可变结果。不要为每次状态读写增加通用 Proxy 来弥补不清楚的所有权。

## 生成文件与兼容范围

带生成声明或由生成流程维护的文件不得手改。修改原始配置、来源适配或生成器后，通过正式入口生成并检查差异。生成失败应修复阻塞，不能手补后用一致性检查冒充生成。

生成流程负责统一格式化，数字数组保持易读紧凑，TypeScript 数据不因换入口变成另一套 JSON 风格。

新增原生动作支持时，同时核对契约、验证、运行时、切面重置和优化器用途分析，并重新生成全部受影响的定义。发布完整候选文件，不从候选中抽取语句补进正式文件；生成文件被格式化忽略表排除时，仍须检查生成入口的格式化结果。

正式发布前可以直接调整开发中的格式和接口，不维护未发布格式的历史兼容层。旧版工具的异构存档属于明确导入范围，不能与开发中格式混为一谈。

## 原生动作边界与无效行为裁剪

转换器保留对 Endaxis 有效的原生行为，不要求为所有原生动作建立运行模型。对最终保留的调用，一个原生动作对应一个动作调用；属于动作内部的目标查询、遍历、批量操作和变量初始化不能拆成外围动作。原生显式子序列和回调保留自己的调用边界。并列的原生类型可以共用实现，但不能合并调用次数、状态或改变顺序。

生成器必须分析所有分支、条件、变量读写、变量声明及承载这些操作的节点，删除对有效结果没有影响的内容。先裁剪无效分支内容，再消除等价分支及无副作用的条件，反向清理失去消费者的写入、计算和变量键，重复到结果不再变化。不能仅统计变量名是否被读取：被覆盖且从未读出的写入，以及仅被其他无效写入读取的计算链，也属于裁剪对象。 静态证明替代查询或写入时，所有保留的消费者必须同步改用证明结果；不能删除生产者却让运行时继续读取原目标组或变量。

分析按真实作用域、执行顺序和资源引用进行，覆盖所有调度、事件、子序列及跨资源变量传递。同名键不代表同一变量。分支等价必须考虑返回值、短路、随机取样、事件、延迟回调和生命周期；条件中的有效写入不能随相同分支一起删除。共享节点不代表只执行一次，切面恢复前后的有效行为必须一致。

有效结果以产品实际使用的战斗状态和输出为准，包括伤害、治疗、失衡、资源、状态及回执，以及能影响它们的后续执行。中间变量、内部编号或节点身份的存在本身不是保留理由；若被后续操作观察，则须追踪到真实消费者。不能为了保留原生结构而创建空执行节点，也不能用固定角度、填零或默认镜头配置让本应裁掉的操作进入运行时。

跨资源变量证明须同时覆盖黑板向接收资源传递，以及其他资源主动查询该宿主变量的入口。仅沿当前资源的外部引用扫描，不能证明 Buff 变量没有外部读取。完整资源集合、动态引用和未解析读取必须显式参与证明；不能把未加载的资源或未知查询当作无读取。

来源识别与运行时支持分开。全量发布资源经过裁剪后某类节点已无有效调用时，删除该类型的正式契约、应用编译、运行和编辑支持，并清理仅为它服务的环境对象、状态、配置和切面字段；生成器仍可保留识别与分析原生输入所需的信息。公共依赖若另有有效消费者则保留，不能按文件整批删除。未来资源重新需要该类型时，再依据有效调用及原生语义接入，不预留无人使用的运行模型。

分析无法证明安全时，不猜测删除，也不伪造行为。明确记录未决依赖及其真实资源入口；若它影响正确生成，应阻止发布。审计应区分未进入发布范围、已裁剪和实际保留，并能从保留节点追溯到有效消费者。全量生成成功和总伤害接近都不能替代这些验证。

同类节点遵循一致的定义、来源解析、转换和执行流程。用途分析共用入口枚举、作用域和读写语义，不为不同裁剪规则另写一套扫描逻辑。每类保留节点须说明原生依据、产品简化及保留必要性；迁移完成的路径同步删除旧实现与中间接口，不长期并存两套同义机制。

较大的迁移分轮验收：记录实际完成项和未决项，检查是否偏离目标、是否在局部问题上投入过多，并据此调整下一轮顺序。局部验证通过不能替代全量资源、运行流程及代码归属的最终审查。

不以逐步浮点计算与原生完全一致为目标。精度问题只有影响条件判断、技能可用性、触发次数、对象生命周期或其他实际行为时才继续追查；不为纯数值微差扩大运行时或长期进行逐指令核对。结果比较可对明确的连续数值字段采用记录在报告中的绝对/相对容差，但事件种类、身份、顺序、次数、时刻和判断结果必须严格比较。不得把容差全局应用到所有数字，也不能借此掩盖公式、参数或乘区错误。

## 注释和验证

中文注释解释用途、单位、状态归属、缺省行为及清理时机。避免只翻译标识符，或用“稳定边界”“公共投影”等抽象词代替实际含义。

测试围绕可能出错的行为：公式边界、执行顺序、来源身份、引用有效性、保存恢复和真实属性路径。UI 整理检查数值、模式、布局和操作，不用固定源码文本证明交互正确。

新增测试须能指出一种具体、重要且现有检查不易发现的错误，并在失败时说明用户会看到什么问题。默认值、常量、单步算术、字段透传、简单条件分派和框架自身行为通常不单独测试；确有业务边界时，用一个覆盖边界的场景验证。删除或合并重复测试时保留能区分正确与错误实现的断言，不按测试数量或覆盖率补回低价值用例。大型生成样本与界面源码扫描要计入执行和维护成本。

提交新测试前，先检查现有单元、集成和正式导出验收是否已经覆盖同一故障。测试若只是把生成定义重述一遍、拿同一对象的两种查找方式互相比较，或为每个资源重复运行同一条通用规则，就不进入常规测试。需要枚举全部资源时，说明资源间的差异为何会改变结果；否则用少量代表性边界样本验证规则。多种输入的笛卡尔积也遵循这一要求。测试夹具和断言应只保留区分故障所需的字段，避免让测试代码量掩盖被验证的行为。

纯类型断言由 TypeScript 类型检查命令负责，放在被相应 `tsconfig` 纳入的 `.typecheck.ts` 文件中；不要包装成运行时没有行为的 Vitest 用例。

不要用源码字符串或正则断言锁定函数名、调用写法、模板片段和 CSS 声明。相同的行为可以有不同实现，文件里存在某段代码也不代表它执行正确。交互检查实际状态变化和事件结果，布局检查浏览器中的展示；已有行为测试覆盖时，不再叠加源码匹配测试。依赖方向、禁止跨层导入等架构规则可以做静态检查，但应检查规则本身，不规定具体实现片段。

完整资源的编译、确定性和候选验收由正式导出流程负责，不在普通测试里保存整套原始快照重复导出。编译器回归只保留问题所需的小样本；模拟回归直接使用生成定义。导出验收未覆盖的特定组合或失败条件仍需测试，但应在能验证该行为的最小范围执行。

界面规则见[界面开发](ui.md)，检查命令见[开发指南](README.md)。交付说明应交代行为变化、验证范围、剩余限制，以及实际修改范围为何合理。

随机取样不因推进随机序列而阻止裁剪。结果不被有效消费者使用时，允许删除取样及其无用输入计算；不以保持后续随机样本一致为保留理由，也不增加占位取样。仍须保留有效结果依赖、作用域及返回值语义。
