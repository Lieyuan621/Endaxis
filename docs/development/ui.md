# 界面开发

公共组件的职责边界另见 [设计系统说明](../../src/design-system/README.md)。

公共控件负责主题、状态、浮层和基础交互，功能组件负责业务布局。复用控件时同时删除已被覆盖的局部 CSS，避免同一个效果由多处决定。

通用控件的职责以实际组件 API 和使用效果为准。业务专用的绘制、拖拽和高频编辑保留在功能组件中；迁移时先确认交互、层级和尺寸是否等价，不因外观相似就替换组件根源。

动作图的节点、端口与连线保留专用语义色；画布、节点表面、工具栏及文字应随深浅主题切换，不能把深色画布硬编码到浅色工作台中。

## 选择控件

从 `@/design-system` 统一导入公共组件，不直接依赖其内部文件。

Element Plus 组件在使用它的文件中显式导入，不在应用入口全量注册。共用样式由入口加载，组件代码随实际使用的页面打包，避免未使用的控件进入启动脚本。

| 用途                     | 控件或约定                               |
| ------------------------ | ---------------------------------------- |
| 操作、页签和选择卡片     | `EaButton`，选择状态使用 `pressed`       |
| 可选择的筛选项           | `EaFilterChip`                           |
| 常规文本、数字和多行输入 | `EaInput`、`EaNumberInput`、`EaTextarea` |
| 选项与开关               | `EaSelect`、`EaCheckbox`、`EaSwitch`     |
| 两侧活动栏               | `EaActivityRailButton`                   |
| 字段标签、帮助和错误     | `EaFormField`                            |
| 弹窗及操作区             | `EaDialog`、`EaDialogActions`            |
| 底部抽屉                 | `EaDrawer`                               |
| 删除图标                 | `EaDeleteIcon`                           |
| 关闭浮层                 | `EaCloseButton`                          |
| 鼠标提示与点击浮层       | `EaTooltip`、`EaPopover`                 |
| 非组件库实现的菜单表面   | `ea-floating-surface`                    |

字符 `×` 表示关闭或移除标签，不代替删除图标。必须保留独立拖动表面的卡片要提供键盘操作和 ARIA 状态。

文件、颜色和范围输入可保留浏览器专用行为。数字字段统一使用 `EaNumberInput`，时间轴等狭窄区域使用其 `compact` 变体；提交业务数值前要过滤空值和非有限数。需要程序立即聚焦的高频原位编辑器，只有在公共控件不能满足焦点时序时才保留原生控件，并在组件旁说明原因、验证键盘操作。增加通用控件变体时，应有明确职责，不能为一个页面新增无意义的通用样式类。

## 样式与浮层

公共间距使用 `--ea-space-1` 至 `--ea-space-6`，时间轴坐标和图形几何不受间距尺度限制。强调色与危险色表面的文字使用 `--ea-on-accent`、`--ea-on-danger`。

浮层背景、边框、圆角、阴影与箭头由公共组件维护。业务 `popperClass` 只指定必要的尺寸、内边距或语义强调色；不要通过 `.el-*` 深层覆盖复制已有公共行为。上下文菜单使用 `--ea-z-context-menu`。

移动端弹窗的视口限制、外层滚动和头尾固定归基础组件，功能页只设置内容区。选择器的尺寸同时作用于输入和弹出列表。

鼠标悬停反馈放在精细指针媒体条件下；键盘使用独立 `:focus-visible`。提示框跟随鼠标附近偏移并约束到视口，不能按状态段长度推算位置。

## 时间轴图层

紧凑模式四条轨道合计填满可用区域，不额外纵向滚动。状态效果处于技能块区域后方，技能区域的底色与遮挡关系必须明确；松散模式允许展开状态行。

竖向刻度只画在技能放置区域，状态区不画。时间刻度、滚动槽和准备期分隔线共用统一样式，不能在局部面板各自重设。

拖动期间保留完整发布结果，不让等待提示或错误推开其他元素。告警和连续组标记应同时可辨认；技能块本身不加浏览器原生 `title`。

技能块、判定点和充能线属于时间轴专用视觉，不用通用按钮外观代替。它们的底色、遮挡和命中层级应与轨道一起检查；只有块上的独立操作按钮才按公共控件职责处理。

## 图片与专属状态

干员头像裁取中心区域时保持宽高一致，避免圆形被布局挤成椭圆。武器、装备和敌人图标使用各自的缩放规则，不能套用头像裁剪。

专属状态按原生素材和 prefab 的坐标、透明区、颜色及填充顺序显示。外观组件只接收数值和进度，不拥有战斗状态，不凭截图相似度发明规则。

## 浮层与鼠标手势

工作区使用 `InteractionSession` 分配手势所有权，同一时刻只允许一个拖动或放置操作。调用方必须先通过 `tryStart` 取得所有权，再创建预览、启动交互模拟或安装移动监听；申请失败不应留下任何拖动状态。

模态窗口和非模态浮层有不同规则：

- 模态窗口使用 `useDialogInteractionBoundary`，打开期间阻止背景操作。
- 菜单、设置气泡使用 `usePopoverInteractionBoundary`。打开时取消已有手势，但不持续封锁背景；后续手势申请会先同步收起浮层，再在同一次按下中取得所有权。无需先空点一次关闭菜单。
- 浮层仍拥有其键盘输入，避免编辑菜单字段时触发时间轴快捷键。Esc 先关闭当前浮层，正在拖动时则取消手势。

非模态浮层的关闭回调可能打开模态窗口，因此交互会话在关闭之后重新检查权限，并禁止关闭期间重入申请。浮层卸载或关闭时注销回调；过期手势的清理不能释放新手势的所有权。

鼠标松开结束手势，模拟结果发布属于之后的显示更新。模拟失败、被替代或晚返回均不能延长鼠标手势，也不能清除后来开始的拖动。指针取消、窗口失焦和丢失松开事件时都应有确定的回退路径。

## 验收

实际检查正常、悬停、选中、禁用和键盘焦点；检查中英文、深浅主题、窄屏和不同缩放。涉及面板时检查打开、关闭、切换、滚动和文本复制；涉及时间轴时检查长段、重叠、拖动及图层遮挡。

组件测试保证行为，浏览器验收保证显示。两者不能互相代替。
