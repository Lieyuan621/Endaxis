# 结果展示与来源分析

显示层从已完成的模拟记录生成曲线、状态条、诊断和伤害明细。它可以合并外观，但不能合并真实战斗实例，也不能为了图形完整而补造命中或来源。

## 同一份发布结果

每轮结果关联本次输入和定义快照。图标、技能名称、技能块宽度和伤害详情都读取这一版本，不能在旧命中上使用当前草稿的属性。

伤害步骤保留每次实际执行的身份与时刻。来源施法可以为空，例如独立反应；这类伤害仍须统计并提供可点击入口。隐藏内部 Buff 或缺少原生图标，只影响外观，不得删除伤害点。

## 状态条与图标

只有同一对象上、相同 Buff ID 且持续时间重叠的实例才合并显示。开始和层数变化处显示图标与叠加层数，降到零时不显示新图标。间隔分开的状态不连成一条，详情可以切换各个真实实例。

Buff 内产生的伤害挂在对应 Buff 的状态行，而不是重复挂到来源干员技能上。攻击者、来源施法和 Buff 挂载对象分别保留。

击飞、倒地、猛击、碎甲与破防共用一行。异常与它产生的破防按实际产生关系合并外观，图标显示异常，角标显示破防层数，详情可查看相关实例；不能按同帧或名称猜测关系。

来自武器或套装的效果可以使用提供者的展示图标，原生 Buff 图标配置保持原义。套装配置选择所属装备 ID，生成定义输出最终路径。专属名称、颜色和 HUD 配置归对应对象，不写进通用投影算法。

专属 HUD 只读数值与进度，不重新计算层数或伤害。素材、坐标、填充顺序和颜色以原生 prefab 及资源为依据。界面规范见[界面开发](../development/ui.md)。

## 对象来源图

来源查询从有序回执建立只读索引，区分产生者、来源、归属、来源施法和直接加成。索引可以重建，不进入切面。

图从选中的命中或状态向前追溯。每条关系按自身发生时的序号选择此前状态，同一个 Buff 在一层、两层、三层时是不同的历史节点。不能从早期命中跳到该实例后来发生的变化，否则会制造错误回边。

附着转化显示产物、转化事件与被消耗状态的关系；每次叠层保留本次施加行为。共同历史节点只画一次，业务关系保持有向无环。

布局使用 Dagre。平行关系经不可见布局点路由，解决库对部分多重边的布局限制；这些点不代表游戏对象。布局、节点数量限制和缩放只影响展示，不能改变查询事实或贡献金额。

带精确 Buff 身份的直接修正在图上折叠到该 Buff 节点，无 Buff 的技能修正保留行为身份。显示名称通过发布快照定位技能、天赋、潜能和配装；不能凭数值或同名处理器猜配。

## 伤害明细和贡献

运行时记录本次实际使用的攻击公式、暴击率、乘区值与直接修正，结果投影负责解释它们。攻击快照必须携带捕获时的来源副本，不能拿命中时仍存在的 Buff 替代快照来源。

来源图回答“效果从哪里来”，贡献回答“已支持的直接加成分配了多少伤害”。两者共用直接修正记录，贡献只追到提供者的归属干员，不沿整个产生链递归分账。

当前贡献分配覆盖显式 `damageScale`、直接 `multiplyValue` 和满足前提的纯加法抗性修正。使用结算时冻结的实际值和自身基线，按对数平均方法分配；加法区内按带符号的增量分配，自身为总伤减去外部贡献，保证金额守恒。

属性槽的注入副本不能重复分配。攻击、暴击、消费收益等未支持分解的内容保留在自身项。缺少冻结值、非正基线、数值不稳定或经过护盾吸收时也退回自身；负贡献保留负号，以表格显示。

## 验证

核对同名多实例、回收后查询、同帧状态变化和历史截止；检查隐藏状态仍有伤害入口。贡献测试要覆盖正负抵消、接近的倍率、多提供者与金额守恒，并证明展示修改不改变战斗结果。

页面验收包含长状态段的鼠标提示、图标点击、实例切换、来源图布局和各主题缩放。模拟测试不能代替这些交互检查。
