# 动作图

动作图描述一个资源执行哪些动作、怎样选择分支，以及参数从哪里读取。本页说明资源归属、共享规则和执行语义；画布操作见[编辑器](editor.md)，来源转换与发布见[游戏数据](game-data.md)。

## 资源与图的归属

技能、Buff、能力实体按原生资源身份分别维护。有程序的定义持有完整主图和宏目录，纯数值定义不需要制造空图。干员、武器和套装负责组织所属定义，不拥有包含全部行为的总图。

来自不同原生文件的资源，即使内容相同也不能合并。不同所属对象的定义也不因原生 ID 相同而自动共享。复用一个已登记定义必须通过明确的资源引用，不能按内容哈希推断身份。

| 内容                                 | 归属                                   |
| ------------------------------------ | -------------------------------------- |
| 主动技能、闪避、原生被动、实体子技能 | 各自的技能定义                         |
| 角色模板注册的连携触发条件           | 每条条件自己的资源图，引用要触发的技能 |
| Buff 生命周期、定时动作和事件响应    | 对应 Buff 定义                         |
| 能力实体及其引用的技能               | 实体定义与独立技能定义，分别保存       |
| 天赋、潜能、武器词条和套装效果       | 启用条件、数值补丁及其所属的独立程序   |
| 公共 Buff、消耗品和合约程序          | 各自的实际资源，不以产品目录划分作用域 |

技能施加 Buff 时保存定义引用和本次参数，不把 Buff 的内部节点搬进技能。原生内嵌回调是否属于独立资源应按来源判断，不能机械拆分所有对象，也不能因内联而丢掉原有资源边界。

## 身份与连接

正式结构由 [actionGraph.ts](../../packages/game-data-contract/src/actionGraph.ts) 定义：资源的 `main` 和每个宏分别持有自己的 `nodes`、`dataNodes`。资源可以保存在同一个生成文件中，文件位置不构成作用域。

- 节点 ID 只在所属图内有效。图内连接不能指向另一资源或宏的内部节点。
- 宏调用通过宏 ID 和参数连接；跨资源调用携带独立资源及入口。
- `$sequence: null` 表示空入口，不能把显式空分支与不存在的分支混为一谈。
- 定义身份、调用位置和运行实例是三件事。同一节点被调用两次，就有两次执行。

执行线表示动作的处理顺序。`next` 表示当前动作之后的同步续接，不表示等待它产生的 Buff、实体或监听器结束。分支选择出口后仍可续接 `next`；结束时间线的动作没有可继续执行的出口。循环通过明确的循环动作和入口表达，不依赖图中的回边。宏不能递归调用。

收集资源依赖时先登记身份再解析引用，用已访问集合终止遍历。资源之间互相引用，不等于要递归展开它们的全部内容。

## 数据连接与变量作用域

数据节点输出数值或布尔值，通过 `valueNode`、`conditionNode` 连接到消费者。编译时绑定表达式，执行时才在消费者的上下文中求值。共享读取节点不会缓存结果，也不会让不同施放共享变量。

变量作用域由原生声明、上下文继承与生命周期决定。局部作用域可以复制或共享父环境；同名变量不代表同一份数据。独立资源可以通过明确上下文访问同一角色变量，不能因此合图。

“全部成立”和“任一成立”保留输入顺序与短路。概率取样、查找后写变量等表达式有副作用，必须保留原调用位置和次数；带副作用的数据节点不允许多个消费者。需要保存一次求值结果时应明确写入执行状态或变量，不能放入定义或 UI 缓存。

数值和布尔引脚不得隐式互转。缺失引用、类型不匹配、数据依赖成环及跨图内部引用都应在校验时失败。

## 分支去重与宏提取

生成器先在同一资源、相同作用域内合并完全相同的分支。比较忽略普通节点 ID，但保留动作参数、执行顺序、显式行为身份和外部资源身份。相同尾部直接共享节点，不再套一层宏；共享程序不合并调用次数或运行状态。

宏用于去重后仍然重复的中间流程。例如两处都有 `P → Q`，但分别接到不同后续，可以共享宏体，由各自的调用节点连接后续。单纯进入时间或前驱不同，不构成提取宏的理由。

自动提取采用以下范围：

- 同一独立资源内至少两份不重叠的直线中间段，输入相同、后续不同，外部不能跳入内部节点。
- 每段包含 8—64 个允许的同步动作；分支、循环、作用域、计时器、事件、伤害派发和生命周期动作不参与自动提取。
- 单入口、单出口，不自动提取输入参数；调用节点的 `next` 连接各自后续。
- 计入宏体和调用成本后，至少减少 4 个存储节点，序列化大小也必须下降。
- 用 `nodeBindings` 保留原调用位置的节点身份；已含宏的资源不再自动提取第二层。

这些阈值是生成器策略，不是数据契约的限制。没有合格候选就不生成宏。策略入口为 [actionGraphMiddleSegments.ts](../../tools/game-data-compiler/src/compiler/optimization/actionGraphMiddleSegments.ts)。

优化顺序为序列简化与分支去重、领域变量裁剪、再次去重、宏提取。宏内部只存一份，各调用保留自己的状态；裁剪和提取都必须保留变量读取时机、随机身份、短路、事件顺序及来源定位。

宏与折叠图不是同一概念。宏用于复用，折叠仅用于整理显示，不创造变量作用域；生成器不生成折叠图。尚未实现的编辑和提取能力集中记录在[待办](../TODO.md)。

## 编译、执行与保存

资源生成先投影为生成器内部定义，再由 `finalizeDefinitions.ts` 统一完成可选优化和必需的数据节点转换。关闭优化或仅生成优化报告时，仍会把表达式转换为节点；正式定义始终只保存常量或节点引用。内部表达式类型只供生成器使用，不进入保存、编辑和模拟接口。

定义经过结构和领域校验后，场景编译器按定义、等级及构筑绑定运行程序。编辑器和项目保存正式定义，不保存编译结果；运行程序不可变，执行状态另存。编译器共享宏程序，不恢复一棵完整展开的动作树。

调用状态记录独立进度、局部变量、计时和订阅关系。保存切面只记录状态和程序引用，不复制程序，不因恢复重新执行初始化。详情见[战斗切面](checkpoints.md)。

伤害、治疗和失衡修正器的 `condition` 引用所属 Buff 图的动作入口。三者共用动作执行器及数据节点，各自提供独立的计算上下文，保留各自侧别、阶段和处理器顺序。动作的 Target 是本次计算的对方对象，不能用 Buff 来源替代。

每个 Buff 修正器持有独立条件实例，即时调用逐动作结束并复位。普通执行及 IfElse 分支正文保留状态，由父动作结束和复位时清理。嵌套调用遇到仍在执行的动作时返回失败，不结束外层动作；返回后恢复外层上下文。切面保存条件动作状态，不保存临时伤害、治疗或失衡计算包。处理器直接读取 Buff 变量的标量参数与图内的数据节点引用是两种不同机制。

修正条件可从属性检查器定位到所属 Buff 图的动作入口。状态详情从同一图提取可解释的必要条件；遇到未解释的判断或写入时明确提示仍有其他条件。摘要只供展示，不参与模拟求值，也不另存一份可执行条件结构。

## 代码入口与验证

技能块右键菜单的“查看执行过程”对当前方案完整诊断重跑，独立于普通预览和切面缓存。记录保存节点执行、具有求值或效果的 Tick、重置、结束，以及实际条件结果和黑板读取值。默认列表隐藏重置和结束；它们不代表分支被选中执行。

诊断按已有施法身份筛选，并保留同步嵌套调用；异步响应只在保留原施法身份时关联。查看器复用原始技能图和资源图，默认只浏览当前调用中的步骤；宏、跨程序及新事件响应可显式进入，通过调用栈返回或跳出。普通条件、循环和作用域的执行器嵌套不单独成为调用层。没有同步父记录的外部执行单列为关联执行，不伪造同步调用栈。

切换步骤只更新当前执行高亮和详情，不移动画布；定位按钮负责居中。进入关联调用时在同一窗口显示原图，各图保留浏览位置。点击节点只查看定义，不改变回放游标。每条记录的回执区间包含同步子执行；直接效果展示扣除子执行区间，内部调用通过独立入口查看。记录限量保存在内存，不进入项目或战斗切面；没有记录的值不重新求值。步进和跳出只导航已完成的记录，不推进或回退战斗。

当前条件详情提供最终判断和真实黑板读取，尚未逐项解释所有非黑板条件操作数。技能宿主的扣费、启动和打断摘要，以及缺少施法关联的延迟响应，仍需补齐展示连接。
