# 战斗切面

切面保存某个完整帧边界的战斗数据。恢复后可以继续提交不同输入，用于旧轴转换、候选位置试算和调试。保存点之间可以分支和回退，不合并分支。

## 保存什么

战斗切面只知道已经提交的输入及其后果。已产生但尚未触发的延迟伤害、Buff、投射物和回调必须保存；尚未提交的技能块与连续组计划由调用方保存。

| 内容                                           | 归属                               |
| ---------------------------------------------- | ---------------------------------- |
| 时钟、资源、技能进度、实体、订阅、黑板和随机流 | `CombatStateGraph`                 |
| 编译后的动作、定义、曲线及回调程序             | 固定程序目录，分支只读共享         |
| 尚未执行的用户安排、连续组游标与候选输入       | 应用层输入排程器                   |
| 已发生的执行记录                               | 不可变回执历史，保存点持有固定视图 |

保存、读取和恢复不执行游戏规则，不扣资源、不发事件、不消费随机数。只有受控步进能够让数据与程序交互。

## 数据结构

切面结构集中在 [src/core/combat/state](../../src/core/combat/state)，按依赖层次组织成六个文件：

| 文件                  | 数据职责                                                 |
| --------------------- | -------------------------------------------------------- |
| `foundationState.ts`  | 黑板、引用、订阅和基础属性数据                           |
| `environmentState.ts` | 时间、资源、随机流、环境和输入状态                       |
| `actionState.ts`      | 动作序列及执行进度                                       |
| `abilityState.ts`     | 技能、冷却、中心状态及能力响应                           |
| `instanceState.ts`    | Buff 容器、能力实体和投射物实例                          |
| `combatState.ts`      | 共享状态、输入、环境、事件、干员、敌人与动态实例的数据根 |

处理程序、运行时类、端口和校验留在业务模块。调用方直接导入所需层次，不增加隐藏依赖的汇总出口，也不为一个字段单独拆文件。

保存点关系是一棵树，但保存的数据本身可以有循环和共享引用。复制必须保留这些身份关系，不能为了画成树而复制同一个对象。

## 保存与恢复

[combatRuntimeSession.ts](../../src/core/combat/runtime/combatRuntimeSession.ts) 提供 `save`、`fork`、`restore`、`discardCheckpoint`、`advanceInputFrame` 及只读查询入口。

保存复制当前数据并固定历史视图。分支只追加自己的数据和回执；父分支不变。恢复先校验程序与引用、建立数据绑定、重建对象关系，全部成功后再替换当前装配。恢复不调用普通初始化，避免重复施加 Buff 或注册事件。

推进禁止重入。步进抛错后会话进入失败状态，只能恢复有效切面或销毁；恢复失败不能破坏原装配。句柄归创建它的会话或排程器管理，持有者应及时释放不再使用的保存点。

完整帧的阶段顺序由 [combatFramePipeline.ts](../../src/core/combat/runtime/combatFramePipeline.ts) 维护：输入前状态与切人、输入前系统、技能输入、战斗系统更新、外部事件及帧完成。首次输入边界由独立状态标记，恢复不能重复或漏交首帧输入。

## 身份与引用

技能施放、Buff、实体、投射物、订阅及动作槽位按保存身份恢复，不能按数组位置重新编号。缺少程序、活对象绑定或合法来源时明确失败，不能吞错后从头重算。

Buff 结束与回收分开：回收回调完成前旧引用仍有效，完成后失效。实例编号在宿主内不复用；已分配但不在活目录中的编号可识别为已回收。未分配编号、错误身份和缺少活容器仍是错误。

技能附属列表可以保留失效 Buff 引用，结束时逐项检查。前一个结束回调可能回收后面的实例，不能只在读取列表时检查一次。其他对象的引用失效时机必须依据各自原生规则，不能从 Buff 推广。

来源身份和读取来源属性的绑定分别保存。保留来源名称不等于必须复活已回收对象；确实需要读取属性的消费者则必须恢复有效端口。

## 回执历史

回执在写入时冻结，使用有序序号定位。封存的前缀由分支共享，当前分支只追加自己的尾段。切面不通过 `structuredClone` 重复复制全部历史。

固定视图用于发布与保存点，增量读取器只读取游标之后的记录。恢复保留前缀而不重放事件。来源索引和 UI 投影可以重建，不保存第二份可变历史。

## 旧轴转换如何复用

[combatInputSchedule.ts](../../src/application/simulation/combatInputSchedule.ts) 同时管理外部计划与战斗保存点。旧轴转换在候选最早可能改变结果之前分支，提交已确认输入和当前候选，读取实际开始、显示结束及终结技变速边界。

尚未转换的旧技能不进入计划。观察分支可能运行到下一待定输入之后，不能直接当作主会话；主会话只推进已确认的前缀。最终新轴完整重跑一次作为验收。

## 性能与验收

当前战斗数据采用完整复制，成本取决于当时的状态量，不是常数复杂度。固定程序和历史前缀共享；候选会话、读取器和保存点需要及时释放。

验证应比较从头运行、分支续算和恢复后的完整状态、有序回执及结果，并覆盖同帧事件、首帧输入、连续组、随机流、对象回收和失败恢复。兄弟分支使用不同输入时必须互不污染。

性能测量应区分状态图、程序、历史、投影和模块加载，不能只看进程 RSS 判断泄漏。可重复的检查命令见[性能工具](../../tools/performance/README.md)。
