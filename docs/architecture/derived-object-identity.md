# 派生对象的身份锚定

方案保存干员轨道、敌人实例和放置在时间轴上的技能块。这些对象在编辑时就有 ID，读档后仍可按 ID 找到。执行方案的过程中，技能可以施加 Buff、召出能力实体、发射投射物，它们又可以施加新的 Buff 或造成伤害。这些在模拟过程中产生的实例，以及每次伤害结算产生的命中，都是本文所说的**派生对象**。同一个 Buff 定义可以在一场战斗中产生多个这样的实例。

伤害详情允许玩家给一次命中指定暴击结果，或指定由这一击打断敌人蓄力。这项选择会影响伤害和后续战斗事件，因此必须随方案保存。下次读档、平移技能或从时间轴中途重新计算时，模拟器需要在结算伤害之前认出玩家选中的那一击。本文把这种跨次模拟识别同一对象的做法称为**身份锚定**。

## 单次模拟中的编号及其限制

一份模拟结果里，每条战斗记录都有帧号和回执序号。它们足以定位当前打开的伤害详情。平移技能会改变命中帧，在技能之前插入无关动作也可能改变回执序号。Buff 和能力实体在本次模拟中分配的实例编号同样可能随创建顺序变化。把这类编号写进存档，重算后就可能指向另一条记录。

技能块 ID 可以跨次保留，但一次释放可能产生多次命中。即使再加上伤害步骤的 key，也只能确定执行了哪一步。同一步可以打中多个敌人，对同一敌人也可能执行多次。此外，独立生效的武器 Buff 可以自行造成伤害，没有可供定位的技能块。为此，方案保存**对象的创建经过，以及它在同一来源下第几次出现**。这些信息既能在重算时重建，也能在复制技能或删除敌人时逐项核对。

## 创建关系与编号规则

编号从可以再次识别的来源开始。对于时间轴上的技能，这个起点是所属轨道的 ID 和技能块 ID。独立生效的构筑效果从效果所属对象和动作 ID 开始。创建记录也可以直接指向干员、敌人实例或整个战斗。

每产生一个派生对象，模拟器就在直接创建者的编号之后追加一段。下表列出参与编号的对象。玩家可以给命中做标记，中间经过的 Buff、能力实体和投射物也需要编号，才能区分它们各自产生的命中。同一行中，只有直接创建者和区分条件都相同，才共用一个从 0 开始的序号。

| 派生对象         | 同一创建者下的区分条件                                          | 计数时机                                                 |
| ---------------- | --------------------------------------------------------------- | -------------------------------------------------------- |
| 普通 Buff        | Buff 定义 ID、挂载对象                                          | 每新建一个实例计一次。刷新或叠层沿用现有实例时沿用原编号 |
| 全局 Buff        | Buff 定义 ID、创建记录中的来源对象                              | 每新建一个全局 Buff 实例计一次                           |
| 能力实体、投射物 | 创建记录中的来源对象，以及实体定义 ID 或发射使用的投射物定义 ID | 每次召出或发射计一次。投射物按能力实体记录               |
| 命中             | 实际攻击者、实际受击者                                          | 每次对该目标结算伤害计一次                               |

例如，技能块 `cast-A` 由干员轨道 `track-A` 上的干员释放，直接对敌人实例 `enemy-B` 造成两次伤害。第二次命中的编号由两段组成。

```json
[
  ["action", "track-A", "cast-A"],
  ["hit", "track-A", "enemy-B", 1]
]
```

第一段选定这次释放，第二段选定该干员打中这个敌人的第二击。如果伤害经由 Buff 产生，两段之间还会多出这个 Buff 的编号。这样，同一技能创建的两个相同 Buff 可以各有自己的「第一击」。若 Buff 挂在另一技能召出的能力实体上，挂载对象也用它自己的创建经过表示，一条命中标记因而可以同时引用两个技能块。

**稳定范围取决于组内顺序。** 移动技能、重排敌人轨道，或插入其他来源的伤害，只要仍然产生同一组命中，便能按原编号匹配。若同一干员在同一技能块内提前对同一敌人多打了一次直接伤害，原先的第二击会变成第三击，标记仍属于第二击。缺少可追溯的创建者、归属对象或受击者时，详情仍可展示该次伤害，但不会提供需要持久保存的标记选项。

### Buff 和能力实体的实例身份

只要创建者和归属可以追溯，Buff 和能力实体在创建时就取得编号，即使它们从未造成伤害也可以识别。编号须先于启动动作登记，因为 Buff 可以在启动时施加另一个 Buff，实体也可以在召出的同一帧运行子技能。从切面恢复时，先前的创建记录已经包含这些实例，继续使用原编号即可。

直接创建者记录在 `producedBy`。来源干员、继承的施法信息和触发这次动作的事件各有用途，单凭其中之一无法补全创建经过。例如失衡时施加的承伤 Buff 记录了动作名 `poise-break`，但其创建入口没有提供 `producedBy`，因此它有本次模拟内的实例编号，尚不能保存跨模拟的标记。

一个 Buff 从创建到结束共用一个编号。技能 A 施加 Buff，技能 B 随后刷新同一个实例时，创建者仍是 A。时间轴上的一条状态段可能合并了多个实例，同一个实例也可能因层数变化被画成多段。因此，标记整个 Buff 时需要选定具体实例。要表达「只标记 B 触发的那次刷新」，还需要能区分该实例经历的各次刷新。

能力实体的编号同样对应一次召出。以投射物为例，技能按目标顺序给甲、乙各发射一枚相同的投射物时，第二枚的编号表示「这次技能发射的第二枚」。如果交换目标顺序，第二次发射时选中的就会是甲。实际受击者记录在后续命中的编号中。

当前存档和剪贴板接受的标记都以命中结尾。Buff 或能力实体本身的标记可以复用已有的创建记录和计数规则。接入时，从详情中选定的运行时实例读取已经分配的编号，并让存档校验与复制逻辑接受以对应对象结尾的编号。读取详情和刷新界面都不应推进创建次数。

## 标记的存储与恢复

身份描述标记属于哪次命中。标记的值另存在方案的 `battle` 中，以下两个字段都以命中编号的 JSON 字符串为键，互相独立。

| 标记                   | 保存值与生效条件                                                                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hitCriticalOverrides` | 伤害允许暴击时，`true` 指定暴击，`false` 指定不暴击。伤害和监听暴击的效果都按指定结果结算。将「暴击」方框切回空框会删除该项                                               |
| `hitWeaknessBreaks`    | 伤害带有 `canBreakWeakness` 标签且实际打中敌人时，可以指定这次命中打断敌人蓄力。`true` 表示仅触发打断事件，`{ stagger: 20 }` 表示先结算 20 点招式失衡。取消勾选会删除整项 |

读档后，模拟器按创建顺序重新编号，在结算每一击时查找对应的标记并检查生效条件。从时间轴中途保存的战斗进度（切面）继续时，模拟器先读取切面之前的创建和伤害记录，按各组已用的最大命中序号接着计数。如果某个条件这次没有触发，方案保留标记，下次再产生对应命中时仍可使用。

## 编辑与复制

删除技能块、干员轨道或敌人实例时，编辑器一并清除标记中引用了该对象的记录。敌人暂时切出，或在原轨道上更换敌人定义时，敌人实例 ID 仍在，标记也保留。撤销和重做会一并恢复或移除对象及其标记。

复制整个方案时，技能块、轨道和敌人在副本中保留原 ID，副本拥有独立的一份标记。复制或剪切选中的技能块时，粘贴会给每个新技能块分配 ID。此时分两步处理标记。

1. **选出随技能复制的标记。** 查看命中编号的第一段。若它指向所选技能块及其所属轨道，就复制标记。同帧独立造成伤害的武器效果有自己的来源，其标记留在原方案。参与增伤的 Buff 也不会仅因改变了这次伤害的数值就被计入创建经过。
2. **替换标记里引用的对象。** 一起复制的技能块全部改用各自的新 ID。同方案粘贴时，干员按原轨道 ID 和干员身份匹配，敌人按实例 ID 匹配。标记引用了未复制的技能块时，该技能块仍在原轨道上就可以继续使用。

跨方案粘贴按干员匹配轨道，所选技能的干员必须在两个方案中各出现一次。双方各有一个敌人时，可将受击目标对应到目标方案的敌人，即使两者种类不同。所选技能找不到唯一轨道时，取消整次粘贴。如果技能可以粘贴，但标记缺少所需对象，或任一方案有多个敌人，则粘贴技能并提示跳过的标记数。

## 操作示例

**只指定多目标攻击中的一击暴击。** 打开技能或状态条上的命中图标。如果图标合并了多条伤害，在详情中翻到目标敌人的那一击。点击「暴击」方框可依次切换为勾、叉、空框，分别表示强制暴击、强制不暴击和使用方案默认结果。设为勾后，同一技能打中另一敌人的伤害仍按方案默认规则结算。将技能块向后拖一秒并重新模拟，只要该击仍然发生，标记会随它出现在新帧位。

**指定一次打断敌人蓄力的命中。** 例如陈千语的战技同时打中两个敌人，只有第二个敌人正在蓄力。在对应的命中详情中勾选「打断敌人蓄力」，填写该敌方招式被打断时产生的失衡值。只有第二个敌人承受这笔失衡，以及陈千语天赋额外造成的失衡。

**复制同时依赖两个技能的标记。** 假设技能 B 召出实体，技能 A 给该实体施加 Buff，随后 Buff 对敌人造成伤害。标记随 A 复制，因为造成伤害的 Buff 由 A 创建。标记里还必须保留 B，才能认出 Buff 挂在哪个实体上。

| 操作                                  | 结果                                                                          |
| ------------------------------------- | ----------------------------------------------------------------------------- |
| 同方案只复制 A                        | 新标记指向 A 的副本和原来的 B。如果粘贴前删除了 B，则只粘贴 A                 |
| 同方案一起复制 A、B                   | 新标记的两处引用分别指向 A、B 的副本                                          |
| 只把 A 粘贴到另一方案，干员轨道可匹配 | 粘贴 A 并跳过该标记。目标方案中即便有同名技能，也不能据此确定哪一次释放对应 B |

## 实现入口

战斗层在创建 Buff、召出实体和发射投射物时记录创建者、定义和归属。[HitIdentityIndex](../../src/core/combat/receipt/hitIdentity.ts) 读取这些记录，[DerivedObjectOccurrences](../../src/core/derivedObjectIdentity.ts) 负责分组编号。这样，即使技能内部改用另一个节点创建相同的 Buff，只要创建者、定义、挂载对象和出现次序都保留，标记仍能匹配。

编辑器通过同一函数 `mapHitIdentity` 访问编号中引用的技能、干员、敌人和实体。删除时检查这些对象是否仍然存在，粘贴时将其替换为对应的副本。暴击和打断敌人蓄力共用这套处理，具体战斗效果各自在伤害结算时判断。[删除标记](../../src/core/project/hitOverrides.ts) · [复制与粘贴](../../src/ui/timeline/interaction/hitOverrideClipboard.ts)
