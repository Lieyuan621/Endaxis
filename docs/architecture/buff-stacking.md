# Buff 叠加、启用与显示

Buff 的叠加方式由战斗运行时执行。结果投影读取实例身份、强化层数和启用状态，不能根据类型名称、施加次数或配置上限重新猜测战斗效果。本页描述当前实现；展示规则不反过来修改生命周期、伤害或属性计算。

## 分组与身份

- 每个接收者的 `CombatBuffContainer` 独立分组，组键为 `stackingKey ?? id`。
- 来源不参与组键。同一目标收到不同来源的同组 Buff，仍执行同一叠加策略；不同 ID 显式使用相同 `stackingKey` 时也会进入同组。
- 同组必须使用相同 `stackingType`。复用型策略选取组内首个未结束实例；所有旧实例结束后再次施加才创建新实例。
- 复用保留旧实例的 ID、定义、来源、技能来源、已过时间及已有黑板。仅 `modify` 合并本次输入黑板；刷新寿命不会替换实例或重新执行 Start/Enable。
- 独立实例有自己的结束时刻和来源。结束不等于立即回收：目录和切面可以暂存已结束实例，但计数、选优和复用忽略它们。

入口见 [CombatBuffContainer.add / BuffStackingGroup](../../src/core/combat/buffs/combatBuffs.ts)。

## 四种不能混用的数量

| 数量     | 含义                                                           | 示例                                                         |
| -------- | -------------------------------------------------------------- | ------------------------------------------------------------ |
| 实例数   | 未结束的独立对象数，包含停用候选                               | 三次 `highPriority` 施加可以保留三个实例                     |
| 强化层数 | 单个实例的 `enhanceCount`，初始为 1                            | `enhance` 可以只有一个实例、三层强化                         |
| 生效层数 | 未结束且启用的实例的强化层数之和                               | 三个 `highPriority` 候选通常只有一个提供一层效果             |
| 显示数量 | 图标采用的语义角标；默认取生效层数，特定身份可以显示明确的等级 | `SpellAbnormal` 的有效 `displayCount` 表示等级，不是新增实例 |

启用实例数是另一项可派生统计：只数启用且未结束的对象，不加总强化层数。它和生效层数也不总相等。

现有 `getCountById`、`getCountByIds`、`getCountByTags` 是**所有未结束实例的强化层数之和**，包含停用候选；`getInstanceCountByIds` / `getInstanceCountByTags` 才是实例数，`getDistinctIdCountByTags` 数不同定义 ID。查询的这些语义不能为了图标正确而改成“只数启用实例”。施加成功次数也不是任何一种层数，刷新旧实例同样可以产生成功事件。

属性修正按实例强化层数创建副本，实际公式继续由属性槽和具体效果定义决定。生效层数不意味着所有伤害、护盾或生命周期动作都统一乘上这个数字。

## 13 种叠加方式

下表的“已有实例”均指同组已有未结束实例。没有已有实例时，所有方式先创建一个初始强化层数为 1 的实例；优先级方式是否启用由选优结果决定。

| `stackingType`                | 再次施加                                             | 寿命或周期                                   | 上限与其他规则                                                             |
| ----------------------------- | ---------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------- |
| `unlimited`                   | 新建并启用独立实例                                   | 每个实例独立计时                             | 不限实例数                                                                 |
| `highPriority`                | 新建候选；保留全部候选                               | 各自计时，停用候选也会到期                   | 只启用排序首位；首位结束后重新选优                                         |
| `stack`                       | 新建独立实例；满组先尝试结束一个旧实例，再启用新实例 | 新旧实例各自计时                             | 正上限限制实例数；0 不限；替换最短剩余寿命的旧实例，同寿命替换较新的旧实例 |
| `enhance`                     | 复用，未满时强化 +1                                  | 不刷新                                       | 正上限限制强化层数；0 不限                                                 |
| `refresh`                     | 复用，不加层                                         | 仅在本次寿命更长时刷新                       | 不读取强化上限                                                             |
| `extend`                      | 复用，不加层                                         | 将本次寿命加到剩余寿命                       | 任意一侧无限则结果无限                                                     |
| `modify`                      | 复用，不加层；合并本次输入黑板并按旧定义重建属性修正 | 不改变寿命                                   | 不替换定义、来源或动作；重建失败会回滚黑板                                 |
| `unique`                      | 拒绝，返回 `null`                                    | 原实例不变                                   | 原实例结束后才接受新实例                                                   |
| `enhanceAndRefresh`           | 复用，未满时强化 +1                                  | 同 `refresh`                                 | 满层仍尝试刷新寿命                                                         |
| `overwriteDuration`           | 复用，不加层                                         | 直接覆盖剩余寿命                             | 有限与无限可以双向覆盖                                                     |
| `enhanceAndOverwriteDuration` | 复用，未满时强化 +1                                  | 强化后直接覆盖剩余寿命                       | 满层仍覆盖寿命                                                             |
| `highPriorityWithMaxStack`    | 新建候选；保留全部候选                               | 各自计时，停用候选也会到期                   | 只启用排序前 N 项；N = 0 时全部停用                                        |
| `timedGrowingEnhance`         | 复用，外部施加可强化 +1                              | 配置寿命是自动强化周期；实例没有普通到期寿命 | 正上限限制强化层数；0 不限；到上限后暂停成长                               |

`stack` 的“先尝试结束”仍走普通 `finish('other')`：若旧实例暂时不可结束，该次替换不会强制突破结束保护，新实例仍会加入。因此不能把配置上限当成对任意中间状态都成立的硬断言，更不能在展示端无条件截断。

### 优先级与平手

仅 `highPriority` 和 `highPriorityWithMaxStack` 读取配置 `priority`，可为固定值或实例黑板值，也支持取负。其他类型，包括 `stack`，运行时优先级均为 0，不会读取残留的优先级配置。

排序依次为：

1. 较高优先级在前
2. 优先级平手时，较长的**当前剩余寿命**在前；无限寿命最前
3. 寿命也平手时，较小实例 ID 在前

数值差的绝对值不超过 `0.00001` 视为平手。`stack` 从排序末尾选择被替换的**旧实例**，不让新实例先参与比较。相同寿命时是较新的旧实例被替换，并非先进先出。

选优发生在候选加入及组成员结束时。它对排序后的成员快照执行 Enable/Disable，每项执行前仍检查实时结束状态，以支持同步生命周期动作改变成员。新首位通常先启用，旧首位随后停用；不能在投影中调换这些事件。

### 上限求值

`stack`、三种普通强化方式、`highPriorityWithMaxStack` 和 `timedGrowingEnhance` 从首次施加的定义默认黑板与本次输入覆盖值求出组上限，并保存为 `BuffStackingState.maxStackCount`。仍有未结束成员时，后续施加的不同上限不会覆盖该值；整组结束后的新一轮重新求值。

省略上限等价于 0。0 对 `stack`、普通强化和定时成长表示不设上限，对 `highPriorityWithMaxStack` 表示没有候选启用。负值、小数、非有限值和非安全整数被拒绝，不表示无限。其他类型不读取此上限。

运行时组计数是执行细节：独立候选型记录未结束实例数，强化型记录强化层数；不能直接把 `currentStackCount` 当作通用显示层数。

### 寿命与强化动作

- 省略寿命表示无限。显式数值须有限；转为 float 后小于 `-0.00001f` 的数值也解析为无限，0 和阈值本身仍为有限值。
- `refresh` 仅在新寿命大于当前值加 `0.00001` 时写入；任意一侧无限，结果无限。`extend` 对有限值直接相加；覆盖策略直接赋值。
- 再施加时，寿命从**本次定义默认黑板 + 本次输入覆盖**求值，不把这些输入并入旧实例，也不重播新实例的来源黑板收集步骤。
- 普通强化首次施加执行 Start、Enable，再执行 AfterEnhance。后续尝试执行 BeforeEnhance，重新检查上限，成功时增加层数并发出 EnhanceChanged，然后刷新属性；最后执行 AfterEnhance。达到上限的尝试仍有 Before/After，不能把尝试事件当成层数已增加。
- `enhanceAndRefresh` 和 `enhanceAndOverwriteDuration` 在强化后、AfterEnhance 前更新寿命；满层也执行寿命更新。
- 定时成长要求周期大于 `0.00001`。大步长会补齐已到期周期；自然成长不执行外部施加的 Before/After。外部强化未满层时保留当前周期余量；达到正上限时重置为完整周期。满层期间停止计时，之后扣层再等待该周期。
- 减少强化层数后重算属性和组计数；扣尽时尝试结束实例。普通结束、手动扣层、再次施加和自然成长是不同事件，不能互相模拟。

算法见 [buffStackingExecution](../../src/core/combat/buffs/buffStackingExecution.ts) 和 [buffLifecycleExecution](../../src/core/combat/buffs/buffLifecycleExecution.ts)。

## 从运行时事实到显示

`BuffApplied` 和 `BuffPresentationStarted` 携带实例当前 `layers` 与 `enabled`。后续真正的启用/停用边界通过稀疏 `BuffEnabledChanged` 记录；强化变化继续由 `BuffStackChanged` 记录。未变化的状态不逐帧重复采样，停用也不伪装成结束或扣层。

投影保留候选的真实实例和寿命，按回执重建其启用区间。停用候选的有效层数、图标和有效显示数量为零；重新启用时恢复该实例当时的强化层数与显示等级。共享实例身份的纯展示子项沿同一事实更新，不能独立重算优先级。

这样所有 13 种策略使用同一规则：先确定实例是否实际启用，再计算有效层数和语义角标。不设 `highPriority → 1` 之类类型捷径，不按 `maxStackCount` 在界面截断，也不把重复 Apply 当作无限叠加。`displayCount` 只解释启用实例的图标等级，不恢复停用候选的贡献。

回执入口见 [standardPlayerDamageEnvironment](../../src/core/combat/runtime/standardPlayerDamageEnvironment.ts)，投影职责见[结果与来源](results.md)。

## 切面恢复

切面保存组成员实例编号、组上限和组计数，也保存各实例的强化层数、启用/结束状态、优先级、剩余寿命与成长周期余量。恢复时先按保存的数据绑定实例，再重建叠层组和父子关系；不重新求组上限、不重新执行 Start/Enable/强化动作，也不因为恢复而追加展示事件。

未来施加仍使用恢复出的组上限，未来结束继续按当前候选排序选优。只保存一个合并图标或一个截断后的层数，不能满足这些分支语义。

### 输入校验、空组与添加冷却

`enhanceAndRefresh` 与 `enhanceAndOverwriteDuration` 在增强回调和层数变更前解析并校验本次寿命，非法寿命不会先执行增强。叠层组类型属于切面状态；成员全部回收后仍保留，恢复空组不执行任何实例生命周期，之后施加仍遵守原类型约束。

添加冷却在创建/叠层前登记，`unique` 等策略随后拒绝本次施加也不撤销。`ignoreAddingCooldown` 只跳过已有冷却检查，不跳过登记。此顺序符合 [combat-spec 的原生添加冷却说明](https://github.com/SQwatermark/combat-spec/blob/refactor/operator-completion/docs/buff-adding-cooldown.md)，不能移到“成功添加后”。
