# 架构概览

Endaxis 把用户安排的技能转换成战斗输入，逐帧执行，再从执行记录生成时间轴和分析面板。编辑器保存用户意图，运行时保存战斗状态，显示层读取结果；这三种数据不能混用。

## 从游戏资源到页面

```text
原始游戏表、资产与原生行为证据
    ↓ 游戏数据编译器
生成定义 + 本地化文本 + 图片
    ↓ 与用户方案中的养成、配装和技能安排组合
场景编译器 → 战斗程序与输入计划
    ↓ 逐帧执行
战斗状态 + 有序执行记录
    ↓ 只读投影
技能宽度、状态条、曲线、诊断、伤害明细与来源图
```

游戏数据编译器在开发阶段运行；场景编译器在模拟一份方案时运行。前者解释原始资源，后者选择本次构筑和输入，两者不互相代替。

## 目录与职责

| 目录                          | 负责什么                                       |
| ----------------------------- | ---------------------------------------------- |
| `packages/game-data-contract` | 干员、技能、Buff、动作和装备的公共数据类型     |
| `tools/game-data-compiler`    | 读取原始数据，生成和验证正式定义及资源         |
| `src/data`                    | 正式游戏定义、数据目录与按需加载入口           |
| `src/core/project`            | 用户项目格式和校验                             |
| `src/core/game-data`          | 定义访问协议，不重复声明公共类型               |
| `src/core/compiler`           | 根据构筑和方案生成战斗程序                     |
| `src/core/combat`             | 时间、技能、事件、状态、伤害、资源及可恢复数据 |
| `src/core/projection`         | 从执行记录生成显示数据和诊断                   |
| `src/application`             | 编辑事务、模拟服务、输入排程及旧轴转换         |
| `src/ui`                      | 页面、手势、定义编辑与结果展示                 |
| `src/design-system`           | 公共控件、主题变量及浮层行为                   |

底层不读取 Vue 组件或 Store。游戏数据契约不依赖应用和生成器；这两端生产代码也不互相导入。集成测试可以同时使用两端，以验证生成内容确实能运行。

## 数据归属

生成定义是可复用的规则；项目保存作者的选择和自定义定义；战斗实例保存本次执行的进度、资源和随机状态。每轮发布结果冻结其使用的展示元数据，避免旧结果读到新草稿。

执行记录在发生时写入并保持不可变。曲线、来源索引和界面选择可以从它们重建，不进入用户存档，也不反过来改变战斗。

全局属性配置经场景编译变成初始化 GlobalBuff，沿普通属性槽参与结算。构筑面板展示养成和配装；战斗加成不另建一套静态面板算法。
