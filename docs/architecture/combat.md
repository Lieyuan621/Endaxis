# 战斗模拟

运行时按固定帧顺序执行输入和游戏程序，维护本场唯一的战斗状态，并记录发生的事实。界面与审计工具共用正式模拟入口，不各自实现伤害或资源算法。

## 执行入口与分工

[runScenarioSimulation.ts](../../src/application/simulation/runScenarioSimulation.ts) 组织场景编译与执行，[runStandardPlayerDamageScenarioSimulation.ts](../../src/application/simulation/runStandardPlayerDamageScenarioSimulation.ts) 准备当前单敌人环境。

`src/core/combat` 按职责组织：`actions` 处理动作序列，`skills` 处理施放、候选和冷却，`abilities` 管理能力宿主与事件响应，`buffs` 管理 Buff 生命周期，`time` 提供时钟，`damage`、`heal`、`resources` 结算数值，`receipt` 记录事实。`runtime` 装配并推进这些系统，不再计算另一份伤害。

执行器不认识的操作应交给明确的后续执行器；最终无人支持时必须报错。新增能力须同时接通生成、环境、执行与预检，仅放宽校验不算支持。

## 时间与技能宽度

战斗时钟以 30 FPS 推进整数帧，不读取墙上时钟。技能、Buff、冷却按各自规则消费局部时间。时间膨胀提供不同增量，不能替调用者决定应该采用哪条时钟。

| 对象                                                  | 使用的时间                                                               |
| ----------------------------------------------------- | ------------------------------------------------------------------------ |
| 普通 Buff 的寿命、周期触发和内部动作                  | 全局缩放时间；终结技将全局倍率降为零时暂停                               |
| 开启 `useTimeDilationDt` 的 Buff                      | 所属实体最终时间，包含自身倍率和忽略全局缩放的设置                       |
| 同时开启 `onlyUseSelfTimeDilation` 的 Buff            | 全局倍率与自身倍率相乘，不采用忽略全局缩放的设置                         |
| 普通定时标记，包括能力实体上的标记                    | 默认使用全局缩放时间，显式开启时间膨胀开关时使用目标实体最终时间         |
| 技能时间线、能力实体寿命                              | 所属实体最终时间                                                         |
| 技能冷却                                              | 通常按未缩放时间推进；当前生效的膨胀明确要求影响冷却时才使用全局缩放时间 |
| 全局 Buff、全局定时标记、共享技力恢复和待释放连携窗口 | 全局缩放时间；连携窗口还可以被显式暂停                                   |
| 失衡恢复                                              | 全局缩放时间                                                             |

“全局对象”和“挂在干员身上的对象”不能直接决定时钟。普通 Buff 即使挂在终结技施法者身上，
也不会因此绕过全局暂停。反过来，普通技能冷却也不会因为 Buff 暂停而停止。
实体累计时间和全局累计时间都保存在战斗切面中，恢复时继续使用保存的进度。

投射物的来源时间同步不是直接借用施法者时钟。原生发射时读取来源 AbilitySystem
的时钟倍率，后续收到倍率通知才复制来源实体的自身倍率，并另行同步忽略全局缩放的开关。
当前编译器明确拒绝开启来源时间同步的持续投射物；支持它需要保存和恢复订阅状态，
不能只放宽校验或逐帧读取施法者当前倍率。

同一技能至少有几种不同的边界：输入帧、费用帧、可操作窗口、显示结束和自然结束。技能块结束不代表 Buff、投射物或能力实体回收。

`timelineBlockFrames` 是定义的局部显示边界。[SkillOperableBoundaryRuntime](../../src/core/combat/skills/skillOperableBoundaryRuntime.ts) 根据实际推进发布 `SkillOperableBoundaryReached`，[timelineDisplayTime.ts](../../src/core/projection/timelineDisplayTime.ts) 将它与启动记录配对。边界在帧内更新阶段观察到，连续组在下一输入帧接续。

没有实际记录时，界面可以用定义宽度帮助定位未执行内容，但这种估计不能用于正式输入排程或冒充模拟事实。完整执行缺失应有记录时，需要排查程序问题。

全局和实体时间膨胀都影响对应对象；只有全局区间在轴上显示特殊高光，终结技全局时间膨胀也走这条路径。曲线名字不能代替作用范围判断。

## 状态、事件和对象寿命

技力属于全队，终结技能量属于干员。检查、扣除、返还和恢复是不同步骤；投射物不建立私人能量账户。

失衡伤害跨过中间节点时发布 `poiseKnotBreak`，沿公共连携条件入口检查监听者；一次修改跨多个节点只通知一次。
节点进度由同一生命/失衡账本的当前值与阈值求得，恢复和切面恢复不会保留过期进度。节点 Buff 与短暂硬直仍未接入，不应把节点事件可用视为完整节点效果已支持。

Buff、元素附着、语义状态和定时标记各有用途，不能因为都画成持续条就合并运行结构。查询与结算必须读取同一实例。

Owner、Source、当前执行对象、来源施法和贡献提供者是不同关系。事件应传递已有身份，监听者不按名称或同帧关系猜测。同步通知可能嵌套，退出内层时必须恢复外层的黑板、来源和目标上下文。

监听由其技能、Buff 或装备宿主管理。结束、释放和回收不能互相代替：投射物回收先结束当前技能，再通知 reset，最后清理 Source，让回调仍能读取原来源。已独立存在的效果不因技能块缩短自动删除。

Buff 回收后的句柄如何处理，见[切面的身份与引用](checkpoints.md#身份与引用)。

## 闪避与输入状态

中心状态保存 `Free / Attack / Skill / Dash`；技能实例保存中断与本次可闪避标记；能力系统保存输入映射与连段偏移；玩家共享状态保存连续闪避计数和窗口。这些职责不合并成一个覆盖所有系统的状态机。

普通闪避通过正式中断入口结束当前技能，更新中心状态并安装原生 Dash Buff。后续攻击依据实际保留的连段映射选择技能，不机械把普攻段数加一。

极限闪避标签提交一次成功机会，由生成的监听器继续判断并执行后续程序。标签不直接写死技力奖励或时间膨胀时长，也不强迫所有内部条件成立。隐藏 Dodge 技能仍使用通用技能运行时，不因为它不造成伤害另建技能系统。

不满足输入条件的已放置操作仍执行并标出原因；程序错误和缺失定义不能降级为操作告警。体力不限制当前产品中的闪避，也不显示在界面。

中心计时器、玩家共享窗口和成功延迟使用不同时间域，必须按原生证据区分。恢复后不得重复提交同一成功事实。

## 伤害和随机行为

伤害动作、结算、承伤、生命写入和事件通知是相邻但独立的步骤。单纯发布伤害相关事件不等于造成伤害；浮点精度在原生要求的地方明确处理。

期望和随机模式共用执行流程。期望模式对 Hit 伤害求数学期望，对暴击后效和其他离散状态采用明确的确定性策略；随机模式使用种子取样。完整规则、限制和待确认事项见[概率事件与随机模式](randomness.md)。

显示层只读取已经发布的暴击率、伤害结果和期望值，不重新抽样。连续数值只有在后续不参与离散条件、索引或身份选择时才适合取均值。

## 验证要点

修改执行顺序要检查同帧输入、同步事件嵌套、正常结束与回收；修改时间要比较局部时钟、实际显示边界和后续独立效果；修改随机行为要比较相同种子重跑、技能块隔离和切面恢复。

总伤害、资源、状态及有序回执都参与验证。不同结果是否正确，依据同版本原生事实判断，而不是选择更接近旧版的数字。
