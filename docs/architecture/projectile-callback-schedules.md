# 投射物回调时间表

本页说明投射物效果如何配置、执行和恢复。Endaxis 使用单敌人木桩近似：生成器把命中、到达等事件转换为相对发射时刻的时间表，运行时执行这些回调，不计算弹道、挂点、空间碰撞或敌人体积。时延会改变伤害、附着和资源循环，但不修改技能动作本身的时间线。

## 职责与数据流

```text
原生发射动作及回调技能 + 导出器时延配置
                    ↓
发射节点中的完整时间表、来源和变量绑定
                    ↓
投射物实例时钟 → 到期回调 → 公共子技能执行器
                    ↓
结束活动阶段 → 延迟回收 → reset 与来源清理
```

导出器负责选择近似模型、发布数值和保留原生动作边界；运行时只负责调度与生命周期。回调正文仍由已有的能力系统和子技能执行器执行，不另建延迟伤害队列。

## 配置与生成

配置分为两层，具体发射覆盖优先：

- [资源预设](../../tools/game-data-compiler/config/projectileSchedulePresets.ts)：按投射物资源提供默认回调时间，注释记录场景、计算依据和近似限制。
- [发射覆盖](../../tools/game-data-compiler/config/projectileSchedules.ts)：按所属资源与 `serverActionIndex` 区分不同发射入口。同一投射物用于不同起终点、返回路径或落点时，可以使用不同时间表。

资源与动作编号只是当前源数据版本的定位键，不是跨版本稳定的存档身份。更新源数据时需重新核对配置是否仍指向相同动作。

预设只供生成器复用。生成后的每个逻辑发射节点保存完整数值时间表，运行时不查预设、不读取原生运动参数，也不自动计算飞行时间。结构相同的发射节点可以参与图归并，但每次执行仍建立独立实例，不能把节点去重变成发射次数减少。

未匹配配置的发射目前按启用回调在发射当刻执行的默认规则投影；这不表示其真实飞行时间为零。新增资源必须核对配置覆盖，不能仅凭生成成功判断时延正确。已有预设缺少启用的回调事件时会报错。

无回调发射仅在明确列入裁剪清单时省略。省略实例也会省略它对宿主引用寿命的影响，因此这是木桩模型的显式取舍，不能推导为原生对象没有生命周期作用。

## 时间与事件语义

[公共契约](../../packages/game-data-contract/src/projectileSchedule.ts)分别保存回调事件的 `triggerFrames` 和活动阶段结束时刻 `endFrame`。

- 帧数相对本次实际发射，基准为 30 FPS，使用投射物实例的逻辑时钟。时间缩放会改变其对应的全局时刻。
- 每个回调的触发列表是严格递增的非负整数；空列表表示不触发该回调。多次发射由多个实例表达，不使用重复帧值替代。
- 调度器按到期时刻执行；同一时刻按回调声明顺序执行。零帧事件在发射时处理，不额外等待一帧。
- 调用前推进回调游标。若回调中显式结束实例，后续待执行回调停止。
- `endFrame` 只结束活动阶段，不隐式调用 `finish`。最后一次回调、活动结束和回收可以是不同时间。

`launch`、`hit`、`block`、`reach` 和 `finish` 保留各自回调意义。成功落地与超时是替代路径时，配置应关闭不采用的事件，不能把所有事件都安排执行。Hit 仍使用绑定目标及标签过滤；其他回调保留各自输入绑定，不能统一替换为敌人。

## 生命周期与切面

每次发射保留独立变量、来源、回调状态和原始施法身份。技能结束不自动销毁已经发射的投射物；实体 Buff、子技能和来源查询继续使用现有能力实体机制。

动作主动结束投射物时，取消未来回调并进入回收阶段，不补发 Finish。回收先结束当前子技能，再通知 reset，最后清理来源，使 reset 监听执行时仍能读取原来源。

切面保存实例身份、已过逻辑帧数、各回调游标、变量和生命周期状态；恢复时重建程序与回调绑定。恢复不重新发射、不重新计时，也不重放已经触发的回调。状态结构见 [projectileScheduleState.ts](../../src/core/combat/state/projectileScheduleState.ts)，公共恢复约束见[战斗切面](checkpoints.md)。

## 命中目标

`hit` 调度通过 `hitKind` 区分 `collision`（碰撞命中）与 `arrival`（到达命中）。碰撞命中在触发时解析有效受击对象，再应用发射时保存的碰撞白名单和标签过滤；到达命中保留发射目标，目标已回收时跳过，不自动改投其他对象。`reach` 回调本身仍独立执行，不因目标失效被一并取消。

原生 `hitOnReach` 表示到达时调用命中路径，不代表普通碰撞关闭。当前无碰撞形状的到达命中资源可直接确定来源；两条路径同时存在时，发射覆盖必须明确 `hitKind`，不能仅凭开关猜测。时点表已包含到达触发的命中，运行时不额外补一次。

木桩默认攻击优先选择敌人本体，避免墨魂提前消失造成延迟伤害丢失。这是模拟的目标选择策略，不代表原生锁定规则；显式墨魂查询、伤害传递和销毁仍保留。伤害执行在创建伤害包前跳过已回收的目标，不把失效句柄当成缺少伤害路由。

## 默认时延的近似边界

默认值按场景选择模型，不把所有弹体都视为相同的三米直射：

| 场景           | 配置依据                                           |
| -------------- | -------------------------------------------------- |
| 普通直射       | 三米有效飞行路程；不再叠加挂点高度或敌人胶囊半径   |
| 变速弹与曲线弹 | 依据对应速度曲线或路径参数估算                     |
| 散射           | 采用可有效命中的代表路径，不用任意小受击体裁掉侧弹 |
| 上抛与落地     | 保留决定落地时刻的高度、重力、最高点及水平地面近似 |
| 固定偏移落点   | 使用具体发射入口的偏移，不能替换成统一航程         |
| 返回雷枪       | 采用一维径向路径，分别计算经过目标和返回到达的时刻 |
| 范围扩张       | 依据半径与扩张速度计算触发时刻                     |

这些是固定场景的近似，不代表任意站位、敌人体型或随机落点下的实机时延。运行时没有可调距离或碰撞模型；校准结果应回写导出器配置并重新生成。技能图中的时间表可以编辑，不自动扩展为一组技能初始化黑板参数。

[独立计算工具](../../tools/projectile-simulator/README.md)仅接收数学参数，辅助估算轨迹和接触时间；它不参与正式生成或战斗执行，不管理战斗生命周期，也不自动写入时延配置。

## 逻辑点目标

技能创建的点目标只保存独立身份，用于目标组查询、计数和逐目标执行，不保存坐标。来源不存在时不创建点；随机点生成保留原生数量循环，方向、半径和位置偏移不参与模拟。能力实体仍保留自身身份、来源和寿命，不依赖出生坐标。地面探测沿用对象高度近似，不引入空间碰撞。

## 修改与验证

新增或调整配置时，核对发射入口、回调种类与顺序、目标输入、重复次数和无回调实例的寿命用途。验证不只比较总伤害，还要检查附着消费、能量恢复、Buff 和能力实体生命周期，以及终止线附近的效果。

运行时修改重点验证零帧执行、同帧顺序、回调内销毁、重复触发、延迟回收和切面恢复。前后结果有差异时，区分时延引起的状态变化与回调丢失或重复；旧弹道结果不能直接作为正确性标准。
