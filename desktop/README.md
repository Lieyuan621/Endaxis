# Endaxis 桌面版

桌面版在共享排轴编辑器上增加了游戏内提示条。你可以把一个方案的模拟结果放在游戏窗口上方，按轴播放技能提示和资源曲线，并核对自己的按键时机。提示条中的数值来自模拟，实战节奏发生变化时可以手动校时。

## 使用桌面版

### 打开方案与提示条

1. 下载 Windows x64 便携 ZIP，完整解压到可写目录，运行 `Endaxis.exe`。便携包自带运行环境。
2. 打开项目并选择方案。首次从网页或开发版转入时，用编辑器的导出、导入功能分别转移项目和干员预设。
3. 等待模拟完成，点击工具栏的「游戏内提示」。修改方案后再次点击即可导出新快照。播放中的提示条会在暂停后载入新快照。

拖动提示条主体可以移动窗口，拖动左右边缘调整宽度，拖动下方两角调整缩放。独立设置窗口可以调整显示范围、不透明度和开始前等待。等待默认 2 秒，可设为 0～10 秒，轴上的负时间准备动作仍会播放。

| 全局快捷键 | 操作 |
| --- | --- |
| `Ctrl+Alt+Space` | 开始或暂停，继续时保留剩余等待时间 |
| `Ctrl+Alt+Home` | 回到起点并暂停 |
| `Ctrl+Alt+← / →` | 延后 / 提前 0.25 秒 |
| `Ctrl+Alt+O` | 开关鼠标穿透 |
| `Ctrl+Alt+R` | 重新载入提示条 |
| `Ctrl+Alt+Q` | 退出桌面应用 |

恢复鼠标操作的快捷键被占用时，应用会禁用穿透。设置窗口可以单独关闭；关闭编辑器后，已打开的提示条仍可继续播放。

### 核对按键时机

Windows 播放期间自动监听键盘和首个已连接的 XInput 手柄，无需管理员权限。输入与计划动作的时间差落在匹配窗口内时，对应图标外圈会亮起。匹配窗口默认为前后 0.25 秒，可调至 0.05～1 秒。亮圈仅确认输入时机，实际施放结果由游戏决定。

| 动作 | 键盘 / 鼠标 | XInput 手柄 | 匹配规则 |
| --- | --- | --- | --- |
| 战技 / 终结技 | 1～4 | LB＋X/Y/B/A | 短按松开后按按下时刻匹配战技；长按达到 0.2 秒即匹配终结技 |
| 连携 | E | RB | 按计划顺序，一次输入确认一个 |
| 切换主控 | F1～F4 | LB＋左/上/右/下 | 匹配手动切人标记 |
| 普攻、重击、下落攻击、处决 | 按住鼠标左键 | 按住 X | 每个播放帧确认窗口内最早的一次未确认攻击；LB＋X 按战技处理 |

反馈使用游戏默认键位。暂停、播放结束或关闭提示条时停止监听；重新开始、手动校时或切换方案时清空确认记录。

### 用屏幕图案开始播放（实验功能）

暂停提示条，在同一显示器上显示参考画面，打开设置并选择「框选并保存参考」。选择稳定的图案后点击「开始监测」。若图案已在屏幕上，监测会等待它消失再出现。连续两次匹配后，提示条从轴起点播放，跳过手动开始前等待，并结束本次监测。

手动播放、回到起点、重载或关闭提示条都会取消监测。参考图保存在本机，完整屏幕帧只在内存中处理。图案识别仅用于开播；遮挡、HDR、分辨率和缩放会影响识别时机。

### 保存、迁移与更新

项目、预设、偏好和窗口配置保存在入口 EXE 旁的 `data/`。迁移时可移动整个便携目录。手动更新时，先退出程序，将新版解压到新目录，再移入原来的 `data/`。

支持自动更新的便携版从入口 EXE 旁的 `update-source.json` 读取镜像地址。URL 留空时跳过检查。配置地址后，程序在启动时后台下载并验证更新，更新就绪后可点击「立即重启」进入新版。编辑器右下角显示准备进度和实际下载量，失败时可查看原因并重试。启动时清理中断的下载及旧版本目录，保留正在运行的版本、等待切换的版本和最近一个较早版本。需要回到最初解压的版本时，退出程序并移走 `.endaxis-versions/current`。

## 开发桌面端

以下命令均在仓库根目录执行，Node.js 使用仓库声明的版本。

```sh
npm ci
npm ci --prefix desktop
npm --prefix desktop start
```

### 编辑器、提示条与原生窗口

依赖方向为 `desktop → src`。桌面编辑器复用网页端的启动流程、路由、项目恢复和模拟器，通过工具栏插槽接入提示条。共享代码不导入 Electron 接口，网页构建产物仅包含网页功能。

| 目录（相对 `desktop/`） | 职责 |
| --- | --- |
| `app/` | 应用启动、编辑器窗口、本地资源协议、便携存储和更新 |
| `renderer/editor/` | 装配共享编辑器，导出当前方案的提示条快照 |
| `features/overlay/main/` | 管理提示条会话、原生窗口、快捷键、输入监听和屏幕捕获 |
| `features/overlay/preload/` | 为各窗口暴露所需的原生接口 |
| `features/overlay/renderer/` | 将快照投影到播放器，渲染提示条与设置界面 |
| `i18n/locales/` | 桌面功能的中英文文案 |
| `build/` | 便携版打包、更新清单生成和签名工具 |

**快照。** 导出时等待完整模拟结果，核对项目版本与活动方案，再把播放所需的动作、时间、费用和资源曲线写入独立的 IndexedDB 快照。播放器从快照读取数据，编辑器继续负责项目与自动保存。

**会话。** 重复打开提示条会复用当前会话。每个会话最多有一个非模态设置窗口；设置窗口发送修改请求，提示条统一保存偏好并回传完整状态。主进程按发送窗口校验原生调用。关闭提示条会销毁设置与框选窗口、释放快捷键和监听，并使尚未完成的截图失效。再次打开会重新读取快照和偏好。编辑器与提示条均关闭后应用退出。

**存储。** 生产版通过固定来源 `app://endaxis/` 访问包内页面和静态资源，主进程将请求限制在构建目录内。Chromium 配置与 IndexedDB 位于 `data/profile/`，移动便携目录后仍能识别原数据库。目录不可写时报告错误。开发启动使用独立配置与存储。

### 验证与打包

| 命令 | 检查内容或产物 |
| --- | --- |
| `npm run type-check`、`npm run type-check:desktop` | 共享代码与桌面端类型 |
| `npm --prefix desktop test`、`npm run test:desktop` | 原生逻辑与桌面界面测试 |
| `npm run build` | 网页产物，输出到根目录 `dist/` |
| `npm run package:desktop` | Windows x64 便携 ZIP，输出到 `desktop/release/` |
| `npm run test:desktop:windows` | 运行打包后的 EXE，验收提示条、设置窗口与便携存储 |

首次打包会下载 Electron 运行时，已有相同版本时直接复用。Windows 成品验收无需安装 Playwright 浏览器。修改窗口或存储时应覆盖关闭重开、异步清理、设置同步，以及移动便携目录后的数据恢复。游戏内快捷键、鼠标穿透和屏幕识别还需在实际游戏画面中验证。

CI 运行测试、打包并保留 ZIP 构建附件，部署由分发者执行。[桌面工作流](../.github/workflows/desktop.yml)

## 发布增量更新

**首次发布。** 用 OpenSSL 生成 Ed25519 密钥对，私钥由发布者保管。首次分发的 ZIP 和后续版本应使用同一公钥。在 PowerShell 中设置公钥路径后，从同一终端打包。版本号由打包脚本自动生成。主窗口标题、更新面板和 ZIP 文件名使用同一版本号，例如 `2026.11.25-T175518`，表示北京时间的打包日期和时间。省略公钥的测试包支持手动更新。

```powershell
openssl genpkey -algorithm ED25519 -out release-private.pem
openssl pkey -in release-private.pem -pubout -out release-public.pem
$env:ENDAXIS_UPDATE_PUBLIC_KEY_FILE = (Resolve-Path release-public.pem).Path
npm run package:desktop
```

**准备更新源。** 在打包前设置 `desktop/build/update-source.json`，或在分发的便携目录中编辑同名文件。更新源可以是任意 HTTP(S) 静态目录，用户也可更换镜像。清单使用客户端内置的公钥验签。

```json
{ "url": "https://downloads.example.org/endaxis/windows/" }
```

**发布每个版本。** 打包时设置原公钥路径，再用对应私钥从 ZIP 生成更新文件。

```sh
python desktop/build/prepare-update.py <便携版ZIP> <输出目录> --signing-key <私钥路径>
```

先上传 `objects/` 和 `manifests/`，最后替换 `latest.json`，确保客户端发现新版时所有文件均已就绪。按哈希命名的对象和清单可长期缓存，`latest.json` 应重新验证缓存。
