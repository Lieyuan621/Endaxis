# 代码与资源规模审计

运行 `npm run audit:size`，查看仓库分类、后缀名、模块、静态资源格式、最大文件及本机 `dist` 的文件数、文本行数和体积。

后缀统计优先识别 `.generated.ts`、`.test.ts`、`.spec.ts`、`.bench.ts`、`.d.ts` 等复合后缀，与普通 `.ts` 分开计算；其他文件使用最后一级扩展名。各组互斥，JSON 的 `suffixes` 保存汇总，文件明细的 `suffix` 保存分组依据。

保存完整明细：

```sh
npm run audit:size -- --json tmp/code-size-audit.json
```

统计当前工作树中 Git 跟踪的文件及未忽略的新文件。删除的文件和符号链接不计入；不扫描被忽略的依赖、临时文件、离线数据。`dist` 单独统计，不计入仓库总量，也不会自动构建。

行数为物理行，包含空行和注释，文件末尾换行不额外增加一行。常见文本格式（包括 JSON、SVG）计行，二进制文件只计体积。体积为文件未压缩字节数，不代表浏览器传输体积或运行内存。

分类互斥，测试和夹具优先于生成产物，其后为静态资源、文档、工具、国际化、应用源码、公共包及其他配置。模块表在每类内按目录细分，避免把生成代码和测试混入手写业务代码。JSON 保留每个文件的分类、目录、行数和字节数，可用于进一步对比。
