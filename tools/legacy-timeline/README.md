# 旧时间轴转换与审计

本工具将旧版工具保存的时间轴转成当前项目格式，再用当前游戏定义模拟。它不复刻旧模拟器，也不搬运旧伤害结果。

网页和命令行共用 `src/application/legacyTimeline`；这里提供离线入口。映射快照随应用保存，运行不依赖旧工作树或 Git 历史。

## 转换文件

使用 Node.js 22.12 或更高版本，在仓库根目录执行：

```sh
npm run convert:legacy-timeline -- '<旧轴JSON路径>' tmp/converted-axis --mappings src/application/legacyTimeline/mappings.json
```

输出目录必须不存在，父目录需要存在。工具只创建新目录，不覆盖原文件。输出 `report.json`，转换可发布时另写 `project.json`；没有可用项目时以非零状态结束。

命令行默认使用智能修复时间。网页导入可选择“保留原时间”或“智能修复时间”，默认保留原时间；不要假定两个入口的默认值相同。

## 时间与主控转换

保留时间模式换算旧时刻和帧率，不按新技能宽度修复衔接。智能修复按旧轴全局顺序处理，每个技能取以下三者最大值：旧实际时间、同轨上一技能的新显示结束、全局上一技能的新开始加旧时间差。

候选处于终结技时间膨胀中时移到结束后的输入帧。中断许可需要试算时，从切面分支逐帧查找，不能假定窗口单调变化。修复以实际显示边界为准，不用技能自然寿命或固定等待量代替。

两种模式均推断主控：默认第一轨主控，其他干员释放普攻、强化普攻、下落攻击或处决时添加普通切人标记，保留已有显式切换。需要解决同帧主控冲突时记录调整，不修改模拟器条件。

转换报告记录时间、形态、主控、资源与序列展开的变化。修复可能改变 Buff 覆盖，不能将修复后的总伤直接视为原轴的精确复现。

## 映射与支持范围

`mappings.json` 保存一次性整理并核对的完整旧身份目录；`legacyLoadDefaults.json` 保存旧加载器的默认养成快照。新轴优先复用这些目录，不逐轴猜测名称或资源。

标准技能按旧身份、类别、段号和变体匹配；早期带时间戳的身份使用明确历史映射，不按时间戳模式泛化。旧单块对应新技能序列时，复用正式技能组规划器展开，不新增旧格式专用项目字段。

`actions` 用于明确核对的单动作覆盖；`guardedActions` 额外检查旧对象与实例身份，避免通用方案 ID 误匹配。它们不是常规补齐每条时间轴的方式。

只迁移输入、养成、配装和支持的场景设置，不迁移旧命中、Buff 或伤害快照。干员自定义覆盖按标准技能处理，并报告忽略项。命中点和效果节点连线不支持，删除后在问题汇总说明；技能块连线按端点身份转换。

未知身份、冲突引用和其他未支持设置必须在报告中保留，不静默换成默认对象。转换目标是旧版异构存档，不兼容开发分支每次格式调整产生的临时格式。

## 审计伤害

```sh
node --experimental-strip-types tools/legacy-timeline/auditSimulation.ts tmp/converted-axis/project.json
```

审计只读项目，分别按存档结束线和完整时长重算，输出文件摘要、截止帧、命中数、期望伤害、来源分账及诊断。没有 `castId` 的公共伤害仍计入，不能因来源施法为空判断漏伤害。

比较前统一定义版本、配装、随机模式和统计截止帧。公开旧轴通常表达可行的先后顺序，绝对时刻可能精度不足；输入告警不直接证明作者排错。发现差异后按命中、状态和原生顺序定位，不能把结果改成与旧版一样作为目标。

## 验证与文件保管

```sh
npx vitest run src/application/legacyTimeline tools/legacy-timeline --maxWorkers=1
npx tsc -p tools/legacy-timeline/tsconfig.json
```

保留原始输入，转换结果和审计放在 `tmp/`。私人存档、整批下载轴和临时结果不提交。可公开的回归只保留必要输入与预期行为，不以单个总伤数字替代完整验收。
